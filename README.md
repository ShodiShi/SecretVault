# SecretVault

Личный зашифрованный менеджер для ИТ-администратора: пароли, серверы, секретные
заметки и задачи. Одна кодовая база на Flutter — Android и Windows. Данные
одинаковы на телефоне и ноутбуке **без собственного сервера**: приложение
хранит зашифрованные файлы в обычной папке, а папку синхронизирует
[Syncthing](https://syncthing.net/).

- Шифрование: AES-256-GCM, ключ из мастер-пароля через Argon2id.
- Никакой сети: ни телеметрии, ни запросов, ни загружаемых шрифтов. В Android-сборке
  нет разрешения `INTERNET`.
- Автоблокировка, очистка буфера обмена через 30 секунд, запрет скриншотов на Android.
- Интерфейс на русском, тёмная и светлая темы, адаптивная вёрстка.

## Установка

**Android.** Скопируйте `app-release.apk` на телефон и установите (разрешите
установку из этого источника). При первом запуске приложение попросит
«Доступ ко всем файлам» — он нужен, чтобы работать с папкой
`Documents/SecretVault`, которую видит и Syncthing.

**Windows.** Распакуйте `SecretVault-windows-x64.zip` в любую папку и запустите
`secret_vault.exe`. Установщик не нужен; все файлы из архива должны лежать рядом.

Готовые сборки создаёт GitHub Actions (`.github/workflows/build.yml`) —
артефакты `SecretVault-android-apk` и `SecretVault-windows-x64`.

## Первый запуск

1. Выберите папку хранилища. По умолчанию:
   - Android — `/storage/emulated/0/Documents/SecretVault`;
   - Windows — `%USERPROFILE%\Documents\SecretVault`.
2. Придумайте мастер-пароль (не короче 8 символов; лучше фраза из 4–5 слов) и
   подтвердите его. **Восстановить забытый мастер-пароль невозможно.**
3. Если в папке уже есть хранилище (его принёс Syncthing), приложение просто
   спросит мастер-пароль.

Профиль Argon2id: 64 МиБ, 3 прохода. На слабом телефоне при создании можно
выбрать облегчённый профиль (19 МиБ, 2 прохода — минимум OWASP).

## Синхронизация через Syncthing

Приложение ничего не знает о Syncthing — оно только читает и пишет файлы в папке.

### Windows

1. Установите Syncthing (например, [Syncthing Tray](https://github.com/Martchus/syncthingtray)
   или официальную сборку с syncthing.net) и откройте веб-интерфейс
   `http://127.0.0.1:8384`.
2. «Добавить папку» → путь `C:\Users\<вы>\Documents\SecretVault`, ярлык
   `SecretVault`. Запомните **ID папки** — он должен совпасть на телефоне.
3. Вкладка «Шаблоны игнорирования» — добавьте строку `*.tmp`
   (временные файлы атомарной записи синхронизировать незачем).
4. Вкладка «Версионирование» — по желанию включите «Простое версионирование»:
   это дополнительная защита от случайной порчи файлов.

### Android

1. Установите [Syncthing-Fork](https://github.com/Catfriend1/syncthing-android)
   (F-Droid или GitHub). Разрешите ему доступ ко всем файлам и отключите для
   него оптимизацию батареи, иначе синхронизация в фоне будет останавливаться.
2. «Устройства» → «+» → отсканируйте QR-код ноутбука
   (в веб-интерфейсе: «Действия» → «Показать ID»). На ноутбуке подтвердите
   запрос на добавление телефона.
3. На ноутбуке в настройках папки `SecretVault` на вкладке «Общий доступ»
   отметьте телефон. На телефоне придёт запрос — примите его и укажите путь
   `/storage/emulated/0/Documents/SecretVault`. Тип папки — «Отправка и приём».
4. Добавьте шаблон игнорирования `*.tmp` и здесь.

### Порядок подключения второго устройства

1. Создайте хранилище на **первом** устройстве.
2. Настройте Syncthing на обоих и **дождитесь окончания синхронизации**
   (состояние «Синхронизировано» / «Up to Date»).
3. Только после этого запустите SecretVault на втором устройстве и укажите ту
   же папку — приложение найдёт `vault.meta.json` и спросит мастер-пароль.

Если создать хранилище на втором устройстве до синхронизации, получатся два
разных хранилища с разными ключами в одной папке. Приложение об этом
предупредит (файлы «не удалось прочитать»), но проще этого не допускать.

### Как разрешаются конфликты

- Каждая запись — отдельный файл `items/<uuid>.json`, поэтому одновременная
  правка **разных** записей на двух устройствах конфликтов не вызывает.
- У расшифрованной записи есть `updatedAt`; при расхождении побеждает более
  свежая версия. Удаление — это «надгробие» (`deleted=true`), а не стирание
  файла, поэтому удалённая запись не «воскресает» с другого устройства.
- Файлы `*.sync-conflict-*`, которые создаёт Syncthing, приложение разбирает
  само: сравнивает версии, оставляет свежую, лишний файл удаляет.
- Папка отслеживается на лету; дополнительно данные перечитываются при
  возврате в приложение и жестом «потянуть вниз».

Часы на устройствах должны идти более-менее верно (автоматическое время).

## Смена мастер-пароля

«Настройки → Сменить мастер-пароль». Записи шифруются случайным ключом данных,
а мастер-пароль лишь «заворачивает» этот ключ в `vault.meta.json`. Поэтому
обычная смена пароля переписывает один файл и не может оставить хранилище
наполовину перешифрованным.

Флажок «Перешифровать все записи новым ключом» создаёт новый ключ данных и
перешифровывает каждую запись — используйте его, если старый пароль мог быть
скомпрометирован. Перед этим убедитесь, что все устройства синхронизированы,
а после — дайте Syncthing разнести изменения. Учтите: у кого остались старые
копии файлов и старый пароль, тот по-прежнему может прочитать *старые* данные —
действительно скомпрометированные пароли нужно менять на самих сервисах.

Если после смены пароля в папке появился `vault.meta.sync-conflict-*.json`
(пароль меняли на двух устройствах одновременно) — оставьте тот файл, пароль
от которого подходит, под именем `vault.meta.json`, остальные удалите.

## Резервная копия

«Настройки → Экспорт в один файл» сохраняет файл `.svbackup`: внутри —
`vault.meta.json` и все записи в том же зашифрованном виде. Его можно хранить
где угодно (флешка, облако) — без мастер-пароля он бесполезен.

«Импорт из файла» объединяет копию с текущим хранилищем по тем же правилам
(побеждает свежая версия). Если копия от другого хранилища или сделана до
смены ключа, приложение спросит мастер-пароль, который действовал при её создании.

## Восстановление при потере устройства

Потерян или украден **телефон** (ноутбук цел):

1. В веб-интерфейсе Syncthing на ноутбуке удалите потерянное устройство —
   оно больше не получит новых данных.
2. В SecretVault смените мастер-пароль **с перешифровкой всех записей**.
3. Смените пароли от важных сервисов и серверов: на украденном устройстве
   осталась зашифрованная копия, и её стойкость равна стойкости вашего
   прежнего мастер-пароля.
4. На новом телефоне установите Syncthing и SecretVault, подключите папку
   (см. выше), дождитесь синхронизации и введите мастер-пароль.

Потерян **ноутбук** — то же самое зеркально: удалите его из Syncthing на
телефоне, смените мастер-пароль, подключите новый ноутбук.

Потеряны **все устройства**: установите SecretVault, на первом экране нажмите
«Восстановить из резервной копии», выберите файл `.svbackup` и введите
мастер-пароль. Без резервной копии и без мастер-пароля данные восстановить
нельзя — делайте экспорт регулярно и храните копию отдельно от устройств.

## Горячие клавиши (Windows)

| Сочетание | Действие |
|-----------|----------|
| Ctrl+F | Поиск по всем записям |
| Ctrl+N | Новая запись |
| Ctrl+L | Заблокировать |
| Ctrl+S | Сохранить в редакторе |

Сочетания привязаны к физическим клавишам и работают в русской раскладке.

## Формат данных

```
SecretVault/
├── vault.meta.json          параметры KDF, соль, завёрнутый ключ данных
└── items/
    └── <uuid>.json          одна запись = один файл
```

`vault.meta.json`:

```json
{
  "format": "secretvault", "version": 1, "vaultId": "…",
  "kdf": {"alg": "argon2id", "memoryKiB": 65536, "iterations": 3, "parallelism": 1, "salt": "…"},
  "keyId": "…",
  "wrappedKey": {"nonce": "…", "ct": "…"},
  "previousKeys": [],
  "updatedAt": 0
}
```

`wrappedKey` — ключ данных, зашифрованный AES-256-GCM ключом из мастер-пароля;
его тег аутентификации одновременно служит проверочным блоком: неверный пароль
не расшифрует ключ.

`items/<uuid>.json`: `{"v": 1, "id": "…", "kid": "…", "nonce": "…", "ct": "…"}` —
`ct` содержит зашифрованный JSON записи и 16-байтный тег. Для каждой записи при
каждом сохранении генерируется новый случайный 96-битный nonce; идентификатор
записи и ключа входят в AAD, поэтому файл нельзя подменить файлом другой записи.

Запись атомарна: данные пишутся во временный файл `.<hex>.tmp` и переименовываются.

## Ограничения, о которых стоит знать

- Имена файлов (UUID), их количество, размеры и время изменения не шифруются.
- Dart не даёт гарантированно затирать память: ключ обнуляется при блокировке,
  но строки с паролями живут до сборки мусора. От вредоносного ПО с доступом
  к памяти процесса не защищает ни один менеджер паролей.
- Буфер обмена очищается через 30 секунд, только если в нём всё ещё лежит
  скопированное значение. На Windows копия помечается как исключённая из
  истории буфера (Win+V) и облачной синхронизации; сторонние менеджеры буфера
  могут эти пометки игнорировать.
- Защита от подбора — это стойкость мастер-пароля плюс Argon2id. Короткий
  пароль никакой KDF не спасёт.

## Сборка из исходников

Нужны Flutter 3.47+ (stable), для Android — Android SDK и JDK 17, для Windows —
Visual Studio с компонентом «Разработка классических приложений на C++».
На Windows включите **режим разработчика** (`start ms-settings:developers`):
без него Flutter не может создавать символические ссылки для плагинов.

```bash
flutter pub get
flutter analyze
flutter test
flutter build windows --release
flutter build apk --release
```

Результаты: `build\windows\x64\runner\Release\` и
`build\app\outputs\flutter-apk\app-release.apk`.

### Подпись APK

Чтобы обновления устанавливались поверх старой версии, APK нужно подписывать
одним и тем же ключом. Создайте хранилище ключей и файл `android/key.properties`
(он в `.gitignore`):

```bash
keytool -genkey -v -keystore secretvault.jks -keyalg RSA -keysize 4096 -validity 10000 -alias secretvault
```

```properties
storeFile=C:/путь/к/secretvault.jks
storePassword=…
keyAlias=secretvault
keyPassword=…
```

Без `key.properties` сборка подписывается отладочным ключом — она работает,
но на другой машине (и в CI) ключ будет другим, и обновление потребует
удалить приложение. Данным это не вредит: они лежат в папке хранилища.

## Структура кода

```
lib/
├── crypto/    Argon2id, AES-GCM, ключи, генератор и оценка паролей
├── models/    запись и метаданные хранилища
├── storage/   папка хранилища, слияние версий, резервные копии, настройки
├── state/     контроллер хранилища, буфер обмена
└── ui/        тема, экраны, виджеты
test/          юнит-тесты криптографии и слияния конфликтов
```

Зависимости: `cryptography`, `shared_preferences`, `file_picker`,
`permission_handler`, `intl`.
